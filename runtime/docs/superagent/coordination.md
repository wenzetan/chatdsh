# Router 调度与上下文执行契约

本文件规定 Engine、Router 与执行会话之间的具体动作。状态和额度采用 [contracts.ts](contracts.ts)，持久写入采用 [storage.md](storage.md)。任务调度、资源释放和人工决定由宿主状态机执行；模型通过受限工具表达计划与执行结果。

## 1. 用户目标与任务计划

用户输入携带 goalId 时继续该目标；未携带时以新 messageId 建立目标。目标固定初始用户消息、当前授权、项目说明版本和预算。目标内的追问、修订意见和任务定向输入保留各自 messageId，并关联原 goalId。Router 创建根任务必须提供 originMessageId，宿主验证它对应当前目标。

目标有两项累计限制：模型请求总数和根任务总数。Router、Worker、子代理均计入模型请求总数；失败、取消与已完成根任务均计入根任务总数。任务独立的请求限制继续生效。重建执行会话、恢复任务或生成新成果版本都不会清空累计计数。

Router 根据当前目标建立可独立验证的任务，指定交付要求、资源与已有依赖。Engine 在创建时记录代码基准、配置版本与来源。没有未批准输入依赖的任务可在资源就绪后立即准备；依赖内容未获授权时保持等待。Router 可以在用户目标内追加任务，超过累计数量或模型额度时产生预算决定。

目标在全部根任务已完成、没有人工决定和未确认副作用、Router 已结束当前协调回合后进入 completed。所有根任务终止且用户终止目标时进入 cancelled。存在审阅、依赖、问题、恢复、预算、未确认操作或尚未由用户处理的失败任务时保持 waiting。单纯的模型自然语言回复不会改变这些判定条件。

## 2. 事件与唤醒

| 输入事实 | Engine 动作 | 模型输入 |
|---|---|---|
| 用户消息受理 | 同事务保存消息、目标、delivery 和 outbox | Router 收到一次稳定输入；定向追问只投递至指定任务，主会话保留原消息 |
| 新任务资源就绪 | 准备独立目录、创建并登记 Agent、确认输入接收 | Worker 收到固定目标与输入清单 |
| 任务报告进度 | 保存真实报告与事件 | 不为每条进度启动 Router 回合 |
| 成果封存、失败或新的阻塞 | 保存状态和对应业务事件 | 向同目标 Router 投递有界协调通知 |
| 子代理报告 | 保存内部结果与真实来源 | 向父 Worker 投递同任务结果引用 |
| 人工决定生效 | 更新决定及所有受影响等待原因，重新计算可执行任务 | 必要时向实际等待者投递回答；资源派发直接由 Engine 执行 |
| 资源释放 | 核对实际退出，结算预留，唤醒公平队列 | 不需要调用模型选择下一个排队任务 |
| Router 回合结束 | 保存实际输出和模型用量 | 没有新输入时保持空闲，已有 Worker 继续执行 |

Router 每项目只有一个有效模型回合执行体。不同目标的通知依次处理，每个回合固定计费目标；不能将同一个调用虚构成多个目标各自独立的调用。同一目标积累的通知按事件范围合并，通知包含起止事件 ID、任务 ID、状态、等待原因、成果 ID、文件数量与验证结果枚举。

协调通知由宿主生成，不包含未批准成果正文、文件差异或工具结果原文。Router 取得代码内容时使用 Git 服务读取明确提交版本，读取参考资料使用登记路径，读取成果正文使用用户显式引用的资源。向另一个任务交付成果内容始终检查该成果与消费任务的依赖授权。主会话直接展示成果卡片及认证内容入口，模型可以引用这些成果的位置。

## 3. 输入投递与未知结果

每次投递先保存 stable deliveryId、目标会话、目标代次、goalId、输入对象摘要与调用来源，再执行真实 DSH inbox 操作。适配器优先使用上游稳定输入标识；所支持基线没有等价去重能力时，由 adapter 在本机受管投递入口和权威日志元数据建立同一 deliveryId 的持久去重记录。

只有实际 inbox 或权威日志确认接收该标识后才能标记 accepted。网络或进程中断发生在接收确认之前时标记 unknown，查询原标识；无法确认时等待用户处理。禁止使用新的 deliveryId 重发相同执行输入。accepted 表示接收，read 表示执行会话已经读取，两种状态分别记录。

模型输入由结构化宿主上下文和用户正文组成，保留原 messageId。恢复时已读输入进入已有历史，未读输入继续使用原标识。新尝试取得自己的执行会话与目录关联，旧会话不再接受可改变业务状态的报告。

## 4. 角色提示词与工具装配

提示词存放于 preset-chat 的独立角色资源，在会话 setup 中装配。所有动态字段来自宿主上下文装配器，提示词版本与配置版本一同登记。模型上下文不能指定 actor、改变 childDepth 或授予应用权限。

| 角色 | 固定职责文本与上下文 |
|---|---|
| Router | “根据当前用户目标安排任务，使用实际工具建立任务与读取状态。说明任务交付要求和依赖。保持目标、权限与预算范围。任务等待用户决定时说明对象与原因。引用实际成果和验证记录。项目文件的应用、提交与恢复通过用户操作完成。”注入 goalId、初始及后续消息引用、实际模型、项目说明、状态摘要、可见资源和剩余额度。 |
| Worker | “完成当前任务并提供可审阅成果。读取宿主提供的代码基准与授权输入，在指定目录执行。根据需要创建一层子代理并整理其结果。使用工具报告实际进度、问题与证据。完成前停止后台写入，提交成果路径集合。验证结果引用实际进程记录。”注入 taskId、attemptId、目录、基准、依赖、参考、权限、命令和额度。 |
| 子代理 | “完成父任务分配的目标，在独立目录中处理固定输入版本。保留输入和验证来源，通过报告工具返回父任务。权限与预算继承父任务。遇到缺少输入、权限或资源时提交具体问题。”注入父会话、同一 taskId、固定输入版本、childDepth=1、目录和额度。 |

系统指令用于解释行为，权限由服务入口和执行器执行。角色工具清单在 Agent 发布前生成，所有 PTC 代理方法使用同一清单。子代理继续创建会话、Worker 改变原项目目录、Router 直接应用成果等调用在服务端拒绝。

DSH 回合结束只说明该回合结束。Worker 报告 ready 后，Engine 核验实际运行进程、成果封存和验证证据，全部满足才进入 review；模型输出里的“完成”不作为业务状态输入。错误在实际发生位置记录，当前失败尝试结束；用户授权后的新尝试独立保存。

## 5. 取消、停用与配置变化

用户停止按钮和结构化命令直接到 Engine，不等待模型名额。Router 的 request_stop 携带来源和对象建议，由宿主生成待确认卡片；有效用户回答才产生停止授权。每条停止授权消费一次，目标集合和 revision 必须匹配。

control 可以选择明确的 goalIds，宿主把对应未完成任务、该目标的 Router 投递和资源清单展开到 scopeDigest 中。停止一个目标会停止该目标的当前协调回合并取消后续投递，其他目标仍可使用同一 Router。待停止执行确认结束后才将目标标为 cancelled。includeRouter=true 表示控制整个项目的协调执行，界面单独列明其范围。

停止根任务时同时停止父 Worker、子代理、终端和后台作业。暂停在当前可确认边界停止新调用，保留已完成输入与目录；尚未确认结束的进程持续显示实际状态并占用资源。停用项目还必须确认 Router 和实际后台执行体已停止，存在活动或未确认进程时拒绝停用并显示具体对象。参考与网络权限收紧时停止受影响进程，重新配置执行器后才恢复执行。

Router 模型切换停止旧执行会话并创建新 router_runs，主会话历史从消息来源和任务事实重新装配。Worker 已有尝试继续使用自己的固定模型；用户修改该任务模型时，先停止旧尝试，再通过恢复决定建立新尝试。任何操作都保留累计目标和任务预算。
