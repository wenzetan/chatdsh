# 项目 Super-Agent 架构与产品契约

当前项目服务保存路径、说明和默认助手，创建入口尚未传递执行模式。本文件规定完整目标；[设计入口](README.md)连接接口、存储、执行算法与验收。

## 1. 项目、主会话和执行会话

项目身份为持久 UUID `projectId`，唯一关联 `{ownerDeviceId, canonicalPath}`。路径使用目标设备的文件系统真实路径，Windows 按卷的实际大小写规则判定。既有项目迁移时分配 UUID；发现两个记录指向同一真实目录时保留记录并报告身份冲突，处理前禁止分别启用 Router。Git 远程地址和展示名不参与身份合并。

每项目只有一个逻辑主会话 `mainConversationId`，与项目记录同时建立并保持稳定。`enter` 是幂等的取得或创建操作；并发请求由唯一约束与单写事务返回同一对象。普通会话使用独立 DSH 执行会话，其历史、待发输入和自动记忆均不进入 Router，用户显式引用的内容按授权范围读取。

Router、Worker 和子代理分别拥有 DSH 内部执行会话。Router 每次模型或预设切换产生新的 `router_runs` 代次；前一个执行会话停止并确认后才发布新代次。逻辑主会话保持连续，实际消息关联真实 DSH 事件。任务卡片属于业务事件，模型输出按真实来源展示。

所有 Agent 均由同一设备 DSH 运行时托管。执行器辅助进程只管理文件、网络与命令权限，不运行第二套 Agent 循环。Worker 的会话、目录与任务绑定，其生命周期由宿主服务持有的 Agent handle 管理。Router 的回合结束不销毁 Worker。`parentSession` 专门保留历史分叉语义，调度关联使用 `projectId/taskId/attemptId/sessionId`。

Router 的事件唤醒和角色提示词使用 [coordination.md](coordination.md)。每个用户目标具有稳定 goalId，根任务、子代理与协调请求共同消费该目标的累计额度，避免只限制单个 Worker 后仍能无限产生任务。

## 2. 启用与创建

`defaultMode` 缺省为 `single-session`。本次创建选择优先于项目默认值。工作会话可以选择 `super-agent`；已有 Super-Agent 时打开项目主会话。普通聊天继续使用原聊天后端；项目 Super-Agent 使用 DSH 工作后端。

Git 检测使用 Git 客户端 API，支持普通仓库、关联工作目录与子模块内的独立项目。记录 `repositoryRoot/gitCommonDirectory/projectRelativePath`。项目处于仓库子目录时，任务检出完整仓库，Agent 的 `cwd` 指向相同相对位置，写入范围限定项目目录及其授权的任务资源。修改项目范围之外的同仓库文件需要扩大范围授权。

| Git 结果 | 界面与服务端行为 |
|---|---|
| 存在 `HEAD` | 可启用；任务创建时记录提交和目标分支 |
| 尚无提交 | 可启用；使用 `kind=empty`，显示“仓库尚无提交，任务将从空代码基准开始” |
| 非 Git 目录 | 选项置灰：“当前项目尚未建立 Git 仓库，无法启用 Super-Agent” |
| 裸仓库 | 选项置灰：“请选择具有工作目录的 Git 仓库” |
| Git 缺失或访问失败 | 选项置灰，显示对应设备与明确原因 |

执行器可用性单独显示。Git 合格时可以建立项目主会话；命令、文件和网络能力不满足任务要求时，任务等待执行配置，相关操作明确拒绝。创建、派发和应用分别重新核对项目身份及 Git 状态。项目使用 detached HEAD 时允许生成成果和应用文件；应用并提交前由用户通过项目 Git 操作建立或选用本地分支，再重新生成审阅版本。提交目标固定为项目当前分支。

## 3. 权限与人工决定

Router 在当前用户目标内自动创建、分派和协调任务，只有调度与已授权读取工具。Worker 只有任务执行、读取授权输入、报告、提问与创建子代理的能力。子代理只属于父 Worker 的同一任务，可读父任务已授权输入并生成内部成果。角色权限由宿主根据真实会话注册决定，所有工具方法和业务服务入口均校验调用身份。

根 Worker 的子代理深度固定为一层，多个并列子代理受资源限制。子代理的写任务目录独立，输入为父任务某一固定工作版本及已授权依赖；这个版本通过宿主封存后交付。只读分析也绑定输入版本。父 Worker 的内部成果整理属于同一任务授权。跨任务引用未应用成果需要建立 `dependency` 决定，列明生产任务、成果 ID、摘要、消费任务集合与用途；得到用户允许后才交付内容。

父任务中间输入和子代理结果使用 scope=internal，只有根 Worker 最终封存的交付使用 scope=task-output。内部结果保留真实生产会话与尝试，可以在任务详情查看；它们不直接进入跨任务依赖、项目审阅或应用。父 Worker 将选定内部结果整理为自己的最终成果后，统一按最终成果授权。

| 决定 | 发起来源 | 授权范围与有效期 |
|---|---|---|
| 依赖使用 | Worker 或 Router 请求，用户回答 | 指定成果摘要与消费任务；成果仍保留时有效；更换版本重新询问 |
| 恢复 | 宿主产生清单，用户选择 | 指定任务、受中断的尝试、当前资源状态摘要；资源状态改变则重新核验 |
| 普通问题与工具审批 | 实际调用关联，用户回答 | 指定问题或 `callId`、状态版本；沿用既有超时与权限范围 |
| 扩大预算 | 宿主产生用量清单，用户回答 | 指定任务与新增额度；记录新的配置版本 |
| 应用成果 | 用户操作或结构化命令 | 指定审阅摘要、目标目录与分支、动作；持久操作记录只能消费一次 |

用户决定不设置自动批准超时。等待期间保留任务与输入，用户可以拒绝、保持等待或终止。批准同一版本、同一范围后不重复询问。用户撤销依赖时停止新的交付和受影响的后续执行，已有报告保留来源标记。生产任务产生新成果时只发布新版本，消费任务仍绑定原版本；需要切换时重新询问并重新验证。

## 4. 项目配置与默认额度

配置结构以 [contracts.ts](contracts.ts) 为准。`routerModel/workerModel` 默认取项目默认模型；缺少项目默认值时取实际部署的默认模型。首次启用前验证提供方、模型、工具调用和所需输入模态。子代理继承 Worker 模型。模型不可达和额度拒绝按真实错误处理，切换模型由用户操作发起。

固定默认值只在 `DEFAULT_LIMITS` 定义。其含义与可配置范围如下，设备实际额度优先限制项目额度。

| 配置 | 范围与消费语义 |
|---|---|
| projectWorkers | 1–32；同时处于准备、执行或拥有运行后台工作的根任务 |
| deviceWorkers | 1–64；本设备全部项目共享，按项目轮流派发 |
| projectModelCalls / deviceModelCalls | 1–32 / 1–64；实际在途请求，Worker 与子代理共享 |
| workerChildren | 1–16；一个 Worker 的存活子代理数量，深度始终为一层 |
| queuedTasks | 1–200；排队根任务，满额拒绝受理新任务并保留输入 |
| taskModelRequests | 1–10000；每次用户授权的累计模型请求次数，包含子代理；达到上限等待用户增额 |
| goalModelRequests | 1–100000；一个用户目标下 Router、全部 Worker 和子代理共同消费的模型请求总数 |
| goalTasks | 1–1000；一个用户目标累计创建的根任务数量，已经完成或失败的任务也计入 |
| taskProcessCount | 1–128；任务及子代理的受管命令进程组、终端与后台作业入口；各自的系统子进程归入对应执行体 |
| taskDiskBytes | 1 GiB–1 TiB；任务私有目录与生成物的使用阈值，按 resourceProbeMs 检测；参考目录共享内容不重复计算 |

Router 的请求使用协调优先级，设备最多预留一个模型名额；设备总模型并发为 1 时使用同一名额的优先队列，不暂停已有请求来虚构即时响应。状态查询、停止与人工回答不依赖模型名额。父 Worker 等待子代理时释放模型调用名额，根任务仍保留任务名额；子代理不重复占用根任务名额。后台作业消耗进程和资源额度。

模型调用前在同一事务中预留次数与可计量的 token 额度；结束后结算，明确未受理才释放预留。结果未知的预留进入核验状态。提供方不能提供可靠 token 预估时，请求次数仍为硬限制；界面将 token 计量标为估算，不能把估算费用表示为严格封顶。达到设备已有额度即停止新请求，预算增加必须取得用户授权。

提供方 SDK 的自动重试关闭，实际模型请求统一经过额度入口，失败按任务状态机处理。请求上下文绑定真实会话、goalId、taskId 和稳定预留标识，禁止通过进程全局变量推断当前任务。

跨设备部署额度由现有模型入口统一预留，任务请求带稳定 reservationId。设备先保存任务次数预留，入口再原子预留提供方额度，两者都确认后才能向模型发送。入口明确拒绝且尚未发送时释放设备预留；结果未知时保留原记录并查询，不能把两个数据库描述为共同事务。直接模型路由同样经过设备预算协调器，无法观察到的外部调用不计入本项目严格额度承诺。

`prepareCommands/verifyCommands` 保存明确 argv 数组，通过已批准的执行环境运行。项目配置的扩大权限变更需要用户操作，收紧权限立即阻止新调用并停止受影响的已运行进程，实际终态未确认时显示未确认。普通说明和模型配置用于新任务；已有任务绑定记录的版本。

独占资源在配置 resources 中登记 id 与 project/device 范围。Router 创建任务时只能选择已登记的 resourceIds，Engine 按规范化后的资源键串行预留。端口或数据库的实际访问方式通过项目准备命令配置，资源名本身不会授予额外文件或网络权限。

## 5. 状态与事件处理

`TaskState` 与 `WaitReason` 分别定义状态和并存等待原因。等待条件全部满足后，只有有效的执行授权、当前代次和足够资源同时成立才能派发。模型报告不能直接移除人工授权、恢复和预算等待原因。

| 原状态 | 输入事实 | 新状态或处理 |
|---|---|---|
| queued | 资源、依赖、执行环境就绪 | preparing；建立执行尝试与持久启动动作 |
| preparing | 目录准备成功并持久确认 | running；按稳定输入标识提交首条消息 |
| preparing / running | 准备、工具或模型执行失败 | failed 或 waiting；记录实际错误，结果未知使用 unconfirmed 原因 |
| running | 提问、审批、预算、用户暂停 | waiting；保留全部同时生效原因 |
| running | Worker 报告完成且无活跃后台工作 | review；生成不可变成果与验证证据 |
| waiting | 用户有效决定、资源释放 | 移除对应原因；其余原因保留；重新核验后排队 |
| review | 用户要求修改 | queued；新尝试与成果版本，原成果保持可读 |
| review | 应用操作得到完整确认 | completed；保存应用及提交关联 |
| review | 用户接受无文件修改的报告 | completed；保存明确的成果接受操作，原项目与 Git 引用保持不变 |
| failed | 用户恢复原目标 | queued；新尝试，保留原失败证据 |
| 任一未终态 | 用户停止并且执行体确认终止 | cancelled；保留成果和记录 |
| 任何活动状态 | 宿主、插件或执行器重启 | waiting，增加 recovery；原状态记录在恢复清单 |
| completed / cancelled | 新工作请求 | 新任务；历史任务状态保持不变 |

执行失败在出错位置记录并结束当前尝试；已经明确结束的尝试不会自动再次启动。用户原目标内的正常验证迭代属于同一有效尝试。对网络结果不确定的请求先查询原操作。读取失败与业务失败均不切换执行体来掩盖错误。

应用旧成果版本时，只有所选版本仍覆盖任务当前完整成果、且无后续活动尝试，才能完成整个任务；否则只记录该版本已经应用，当前任务保持待审阅或执行状态。报告型成果提供“接受成果”，空文件差异不会创建占位提交。

事件和待执行动作使用事务记录，模型输入用稳定 delivery ID 提交。只有 DSH inbox 或权威历史已经确认收到该标识，才能记为已投递。回合结束、作业结束、报告和输入接收事件都通过同一命令服务更新任务，旧代次报告保留执行证据但无法改变当前任务。

## 6. 上下文与长期记忆

上下文装配使用宿主登记的项目归属，注入用户目标、项目说明版本、代码基准、权限、依赖授权、参考路径和实际模型。Worker 默认不继承 Router 全部历史，长内容通过带来源的资源引用分页读取。

Router 的完整任务与授权事实从数据库查询，模型摘要仅用于减少上下文。记忆通过[平台标准接口](../plugin-platform.md#6-记忆标准接口)使用用户选择的插件，Super-Agent 默认关闭全局自动召回和自动写入。项目明确启用指定范围后，Worker 只能读取获准事实，未应用成果不进入共享记忆，人工确认的项目事实才交给所选插件保存。提供方不可用不改变任务授权或业务状态。

提供方适配器必须验证 Router、Worker 与子代理的原生监听和后台整理范围。无法过滤这些内部会话时，拒绝启用对应自动行为。工具可见性收窄不作为后台读取和写入约束。每个目标保存能力绑定快照，已有任务的记忆操作继续使用原提供方。

共享参考目录按需读取，记录实际读取文件的摘要和时间。这些业务记录不进入遥测。用户或外部工具更新原始资料后，后续读取可以取得新内容；跨文件一致版本与旧内容恢复不作冻结承诺。内容变化影响任务结论时重新核验相关资料和验证结果。

## 7. 客户端页面与操作

创建入口显示类型、设备、目录、执行模式、模型和权限。选择 Super-Agent 后显示项目 Router 和 Worker 的实际模型；已有主会话时操作文案为“进入项目 Super-Agent”。模式默认来自项目，普通会话创建行为保持独立。

项目主会话包含消息区、任务列表、人工决定区和成果审阅区。任务详情显示目标、状态与等待原因、基准提交、目录、模型、权限、依赖、子代理、作业与验证。后台进展只更新任务记录；提问、失败、审阅和完成产生主会话可见事件。所有消息关联实际来源，子代理结果由父任务整理。

输入区显示当前目标及其剩余额度，用户可以选择继续当前目标或建立新目标。针对任务的追问固定关联该任务原目标，不能通过更换消息 ID 重置已有任务预算。多个目标在同一主会话展示，目标进展与模型消息使用独立的业务事件。

依赖授权卡片显示成果版本与消费任务，允许批量选择明确的任务集合。恢复页一次展示本项目的执行中和排队任务、后台进程实际状态及未确认操作，可恢复、保持暂停或终止。回答仅消费相同 revision 和 scopeDigest 的决定。

成果页先准备完整候选与验证，展示新增、删除、重命名、二进制、权限、子模块与 LFS 变化，按文件分页并提供完整内容。审阅固定摘要，支持提交修改意见。按钮为“应用”和“应用并提交”；后者展示目标分支、提交信息及作者身份，缺少身份时在写入前要求配置。提交信息遵守目标项目的提交规范。

审阅面板明确选择所需动作，候选、验证和提交钩子按该动作准备；切换动作后显示新的候选，最终按钮消费其固定摘要。目标分支显示当前实际分支，切换分支后需要重新审阅。已应用依赖及其后续变化在依赖区列明，用户能够检查本次实际包含的文件。

应用期间显示真实阶段。冲突、验证失败和中断分别展示对象和实际状态；继续操作绑定已核验状态摘要。多窗口通过 SSE 和 revision 更新，旧设备响应不写入当前视图。离线只保留草稿，长任务在设备侧继续；新消息和决定不建立离线重发队列。Web、PWA 和桌面共用这些组件，本机 CLI 通过相同用户接口管理本机项目。

所有按钮具备标签、键盘焦点和读屏状态；人工决定卡片不覆盖用户草稿。窄屏使用全宽任务与审阅页面。完整功能按真实接口返回呈现，未完成平台能力显示具体原因。

外壳路由为 `/projects/:projectId/superagent?device=:ownerDeviceId`，任务详情附加 `/tasks/:taskId`，成果审阅附加 `/reviews/:reviewId`。未登记目录选择 Super-Agent 时显示项目登记表单，取得稳定 projectId 后调用 enter。模型、参考与网络配置按启用表单明确展示，使用默认值也返回实际生效值。

设备导航桥增加版本化的项目目标 `{kind:'superagent',projectId}`，会话目标继续携带真实 sessionId。握手声明 `superagent-project-navigation` 能力，只有内容端实际打开项目页面后才返回 selected；缺少能力显示需要更新组件，不能打开另一条默认会话替代。外壳保持一个活动设备 iframe，同设备通过该导航消息切换到项目面板，跨设备重建 iframe。SA07 同步交付桥的共享 schema、宿主与内容端校验，并保持普通会话导航兼容。

## 8. 生命周期与数据清理

项目所属设备持有 Router 单写锁，数据库同时保证有效 Router 唯一。重启生成新代次，旧代次无法写入。新设备接管必须由用户发起，确认原执行已停止并传输完整状态；设备失联和租约超时不会自动建立第二个 Router。

关闭客户端、归档入口、停用能力和清理数据分别处理。归档只改变导航可见性。停用前展示活动任务与处理决定，用户暂停或终止任务，并确认 Router 与后台执行体已经停止后关闭新分派；待审阅成果保留。删除项目配置保留 projectId 与主会话关联墓碑，活动任务未处理时拒绝删除；再次登记相同目录复用原身份，明确永久清理后才释放关联。

重新启用使用明确的 enable 操作，返回原主会话与原成果。旧任务继续保留暂停和恢复决定，用户可以选择恢复范围，也可以建立新目标。已结束目标保留记录，新目标有独立累计额度；原任务的额度与身份不会迁移到新目标。

已应用且无依赖引用的执行目录默认保留 7 天，可设置 1–90 天；未应用成果、待决定操作、未确认写入与依赖仍使用的对象不自动删除。业务事件和审阅证据按部署保留政策归档，回收时先减引用，再删除无引用对象。参考资料不由任务清理流程删除。

备份把 SQLite 一致快照、DSH 日志检查点、成果与应用恢复对象、配置和必要的任务工作内容列入同一清单。共享参考资料列出来源和已读摘要，实际内容按用户选择备份；缺失时报告可恢复范围。恢复写入隔离目录，所有未完成任务等待用户决定。普通会话 fork 只继承历史与成果引用，活动任务执行权保留原设备。
