# Super-Agent 实施顺序与真实验收

每个工作包的输入为本目录的完整契约。交付同时包含生产实现、真实验证、遥测调用与包声明、操作文档和复现证据。下表表达依赖，不能通过仅保存配置、静态页面或替代执行器宣布完成。

## 1. 包与公共入口

| 实施位置 | 职责 |
|---|---|
| `@chatdsh/core-contracts` | 迁入严格 schema、共享类型、错误、默认额度、状态迁移定义 |
| `@chatdsh/adapter` | DSH Agent handle、inbox、setup、工具注册与权限服务的唯一上游接触位置 |
| `@chatdsh/host-superagent` | Engine、SQLite、actor、授权、outbox、Git、执行器、成果、应用日志与恢复 |
| `@chatdsh/tool-superagent` | 会话作用域复合工具、按角色的方法目录、运行时身份检查 |
| `@chatdsh/client-superagent` | 项目主会话、任务与决定、成果与应用恢复组件 |
| `host-projects/client-projects/client-shell` | projectId、执行模式、进入既有主会话与设备导航 |
| `preset-chat/bundle-hosted/bundle-desktop` | Router、Worker、子代理预设、宿主服务、会话工具与客户端组件装配 |
| 标准能力服务、提供方适配器、`host-llm-router/core-limits` | 角色与上下文范围、项目记忆授权、原生后台行为约束、原子额度预留和公平调度，接口采用[平台契约](../plugin-platform.md) |
| `gateway/host-device-link` | 签名用户命令、所有者路由、只读业务副本、事件中继 |
| `client-cli` | 本机项目进入、状态、回答、审阅引用、应用与恢复的结构化命令 |

所有生产业务模块通过 adapter 访问上游；SRT、Docker、Git 和 SQLite 由宿主封装成窄接口。文件、命令及终端适配器在会话 setup 发布前安装，默认工具层无法绕过角色与执行范围。新增组合行按实际包名登记，无独立的每项目 profile 或每 Worker DSH 进程。

## 3. 验收清单

| 编号 | 实际验证要求 |
|---|---|
| AC-SA01 | 原项目迁移分配稳定 projectId，路径别名冲突拒绝重复 Router，配置删除和重建保留身份关联 |
| AC-SA02 | 两个真实客户端并发 enter 返回同一主会话；重复操作同摘要回放、异摘要拒绝；旧代次不能写入 |
| AC-SA03 | SQLite 状态、事件与 outbox 同事务提交；提交前中断不发布事件，提交后中断仍能查询原意图；用户操作和真实 DSH 消息来源分别去重，流式检查点中断后恢复原消息 |
| AC-SA04 | 决定必须源自用户身份，Agent 无法通过直接工具、HTTP 或伪造 actor 获得授权；匿名入口、伪造 Origin、重用 bootstrap 票据与被撤销访问会话全部拒绝 |
| AC-SA05 | 普通仓库、关联目录、子目录、子模块项目与无提交仓库建立独立任务；非 Git 和裸仓库置灰并拒绝派发 |
| AC-SA06 | 两个 Worker 的索引和引用独立；共享基准对象只读；枚举全部可见对象仍无法读到原项目暂存内容、其他 Worker 成果或审阅计算内容；任务创建后源 HEAD 更新不改变已记录基准 |
| AC-SA07 | 文件工具、命令、终端、后台作业实际尝试修改源项目和参考目录都被拒绝；其他任务和宿主私有数据不可读取；真实并发替换路径和符号链接时不能越过已授予目录 |
| AC-SA08 | 共享参考目录不生成复制品，原资料更新后新读取可见；映射越界、硬链接别名和文件覆盖检查有效 |
| AC-SA09 | 受管并发入口、磁盘阈值、网络与 prepare 超时实际超限；helper 异常退出时回收自身进程树，脱离原进程组的后代仍可确认停止，不误处理用户其他进程；磁盘阈值与文件系统硬配额分别报告 |
| AC-SA10 | 真实模型根据目标创建并行任务；回合结束但后台运行时保持实际执行状态；失败不虚报完成 |
| AC-SA11 | Worker 创建多个一层子代理成功；子代理继续创建、跨任务父子绑定与角色伪造全部拒绝；父级停止向实际执行体传播 |
| AC-SA12 | 未批准依赖不能读取内容；批准的版本和消费范围可复用；换版本、撤销、循环和跨项目关联正确处理 |
| AC-SA13 | 父 Worker 等待子代理时不会因模型并发名额耗尽形成死锁；跨项目公平派发与有界队列实际生效 |
| AC-SA14 | 并发预留不会重复消费同一剩余额度；Router、Worker 与子代理共同受目标累计额度限制，重建会话和完成任务不清空计数；结果未知保留预留；预算耗尽等待用户决定 |
| AC-SA15 | 候选包含完整依赖并使用实际代码验证，产生不可变版本；模型后续改动无法改变已经展示的审阅内容 |
| AC-SA16 | 项目同时有已暂存和未暂存修改，应用并提交仅包含批准成果，原暂存意图、intent-to-add、未受影响的索引标记与其他文件保留；共享索引、第四版索引和稀疏检出通过原生 Git 处理；上游成果已经应用、下游依赖及重复纳入同一成果使用真实树合并；重叠冲突明确展示 |
| AC-SA17 | 空仓库首次应用并提交只产生用户批准的首个提交；apply 不自动提交；报告接受不产生占位提交；目标分支改变使原审阅失效 |
| AC-SA18 | 在应用各个文件、索引、提交对象和引用发布阶段中断进程，重启后逐项核验并询问恢复；已发布提交不重复创建 |
| AC-SA19 | 校验钩子修改代码或提交信息后生成新审阅；签名与作者身份错误在写入前或实际阶段明确报告 |
| AC-SA20 | 重命名、文件模式、大小写、符号链接、二进制、LFS、子模块对象和缺失对象均有真实仓库案例，无法合并时提供完整冲突 |
| AC-SA21 | Linux、macOS、Windows 分别用实际后端测试；不支持的版本、网络模式和隔离能力明确拒绝，缺平台不代替通过 |
| AC-SA22 | 普通会话历史与全局记忆不自动进入 Router，未应用成果不进入共享记忆，原生监听遵守角色范围，关闭记忆不影响任务运行 |
| AC-SA23 | 执行设备离线不转移任务；SSE 断开、重复、旧世代、慢消费均能正确读取；已受理任务与离线草稿分开处理 |
| AC-SA24 | 创建选择、进入已有主会话、任务与子代理详情、依赖回答、报告接受、成果审阅和应用可通过真实接口完成 |
| AC-SA25 | 多窗口竞争决定或应用只生效一次；过期审阅显示冲突；刷新不会重发用户操作；关闭窗口不停止已受理任务 |
| AC-SA26 | 320–1440 CSS 像素、键盘导航、焦点恢复、读屏状态与长差异分页完成 DOM 和交互验证 |
| AC-SA27 | 全部动作有 span、失败事件与计数，关闭任一遥测入口后无 SDK/exporter/traceparent 且业务结果相同；备份隔离恢复、容量和清理引用均通过 |

## 4. 证据与完成标准

每个案例记录测试 ID、系统和依赖版本、执行命令、退出码、独立数据根、原始对象摘要、实际状态、遥测查询和清理结果。用户正文、凭据、参考资料内容和真实用户数据不进入报告。模型验收使用真实提供方和真实工具，断言业务状态、权限和文件结果，不根据固定自然语言句子判断成功。

应用中断测试在受管子进程的已确认阶段直接终止进程，重新启动真实宿主并读取数据库与文件。数据库约束检查只证明 SQL 约束，不能代替 HTTP 身份、执行器或模型验收。所有必要 AC 完成后才更新 acceptance、ui-feature-inventory 与文档总纲台账。

设计附件检查使用 [verify.mjs](verify.mjs)、[verify_git.mjs](verify_git.mjs) 和 [verify_links.py](verify_links.py)，复现结果见 [verification.md](verification.md)。它们验证开发契约的内部一致性与 Git 算法条件，不登记功能通过。
