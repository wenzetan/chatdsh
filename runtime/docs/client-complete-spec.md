# 完整客户端交互规格

## 1. 适用范围与证据

本文件规定客户端的目标交互、字段、状态与验收条件。实现程度由[界面功能清单](<ui-feature-inventory.md>)记录，已运行的验收证据由[验收状态](<acceptance.md>)记录；本文件中的验收编号表示实现必须满足的条件。目标形态遵循[目标形态](<target-shape.md>)，模块与席位遵循[客户端模块](<client-modules.md>)，尺寸与配色令牌遵循[界面基础设计](<ui-baseline-design.md>)。实施范围与依赖见[实施工作包](<implementation-work-packages.md>)。

可浏览入口为[完整设计稿](<ui-design/complete.html>)；场景编号 S01–S32 与地址 fragment 一致。入口提供配色、画板宽度、状态选择，每个场景包含相关表单与状态画板。设计画板明确标注示例数据与未连接业务服务，画板交互只用于检查导航、字段和反馈。真实业务验收必须连接真实控制平面、运行时、存储与所需外部服务。

已核验的实现依据：

- [外壳页面](<../gateway/src/shell.ts>)与[聚合会话](<../gateway/src/sessions.ts>)由控制平面提供；目标在设备全部离线时仍提供列表与明确的不可写状态。
- [共享组件](<../packages/core/ui-kit/src/components.tsx>)已有面板、列表、按钮、骨架和反馈；目标补齐字段、弹层、菜单、查看器及语义属性。
- [项目界面](<../packages/client/projects/src/client/index.tsx>)、[制品界面](<../packages/client/artifacts/src/client/index.tsx>)、[助手界面](<../packages/client/assistants/src/client/index.tsx>)、[记忆界面](<../packages/client/memory/src/client/index.tsx>)当前主要展示列表或状态；目标包含本文件规定的完整操作。

## 2. 不可变的交互规则

### 2.1 设备、会话与访问

1. Web、PWA、桌面加载控制平面的同一份外壳；当前窗口只保留一个活动设备 iframe。更换设备卸载旧 iframe，聚合侧栏与客户端草稿保留。同设备切换通过经过验证的会话导航通道打开指定 `sessionId`，导航完成前显示正在打开，禁止把目标设备的默认会话当成已选会话。
2. `deviceId` 与 `cwd` 创建后固定。头部、发送区、终端与文件操作始终标明目标执行设备；工作区按显示名聚合，展开后必须显示设备与路径。记忆组关联独立设置。
3. “在远程继续”使用源会话与源设备。“在本机继续”在已登记且在线的本机运行时创建 fork，用户选择本机目录，新会话保存 `parentSession`。Web/PWA 没有可用本机运行时时禁用此动作并说明原因；其他设备目标使用明确的设备名称。
4. 单用户部署不建立账号表、账号注册、个人资料与租户切换。访问层可配置密码、通行密钥及双因素认证；访问会话、设备令牌、执行设备归属分别管理。
5. CLI 仅连接本机运行时，列举本机工作区和会话。制品、分享、记忆等通过命令操作；跨设备继续使用图形客户端。非交互与 ACP 的会话执行也保持本机归属。
6. 所有用户界面、提示、导出默认视图和公开分享均不显示副本水位、同步落后条数及同步档位。内部游标用于续传和去重。界面可显示设备在线状态、业务内容范围、建立时间、记录数量与空间占用。

### 2.2 离线、草稿与消息队列

- 客户端离线和目标设备离线分别显示。控制平面可达且目标设备离线时，侧栏继续提供已知会话，阅读副本使用明确的只读入口和内容读取时间。副本缺失显示未保存可读内容。
- 离线只保留草稿：文本、引用标识及已确认的附件元数据按客户端、窗口、设备、会话保存；窗口标识在该窗口刷新时保持稳定，第二窗口使用独立标识。录音和未上传文件字节不自动持久化；需要重新选择的附件必须显式标注。草稿不存入 Service Worker 请求队列。
- 目标离线期间点击发送，立即显示“目标设备离线，发送失败，草稿已保留”；不写入待发队列、不改变执行路由、不创建回合、不自动重发。网络恢复只恢复读取与可用性，发送需要用户再次操作。
- 在线执行中的消息队列可以保留。每项显示内容摘要、目标会话、顺序和状态，支持编辑、删除与受宿主支持的立即发送。队列只在同一目标仍在线且宿主确认当前回合结束后消费。连接断开、目标离线、访问失效时暂停自动消费；恢复后重新读取确认状态，由用户显式恢复待处理项目。已确认接收的消息按幂等键查询状态，不重复提交。
- 审批、提问应答、创建会话、终端、文件修改、配置保存在目标离线时明确失败。审批卡片保留并重新读取状态，禁止排队决定。停止请求失败显示“停止请求未确认”，不能提前显示已停止。
- 网络超时后无法判断写入结果时显示“结果尚未确认”，保留操作标识，先查询实际结果。禁止通过自动重复写入掩盖不确定结果。
- 草稿写入失败、存储额度不足、隐私模式或浏览器清理均要提示；退出访问会话前提供清理本客户端草稿的选项。凭据、记忆查询内容与工具原文不进入草稿持久化。

### 2.3 表单和写入

每个表单具有明确标题、字段标签、帮助文本、必填标记、当前设备与设置作用范围。页面读取服务提供的 schema、限制与 `revision`；下文明确的产品限制由客户端与服务端共同校验，服务端限制收紧时界面展示实际限制。

- 文本在提交时规范化外围空白；指令、提示词、JSON 和用户消息保留原内容。空白必填值不得提交。路径由目标设备验证绝对路径、存在性、权限与允许范围。
- 字段变更标记未保存；底部保存栏提供保存和取消。切换设备、设置区段、关闭窗口或浏览器离开时保护未保存输入。离线保存明确拒绝，普通表单内容作为本地草稿保留，敏感认证字段不持久化。
- 提交期间锁定当前动作与受影响字段，其他页面仍可阅读。成功后使用服务器返回值；失败保留输入，在字段与错误摘要显示具体问题，摘要链接聚焦对应字段。
- 重复点击共享同一个操作标识；危险动作列出名称、设备、范围、可恢复性与进行中操作影响，取消不发送请求。危险确认默认聚焦取消按钮。
- `revision` 冲突保留编辑稿和服务器值，提供重新读取、查看差异、逐字段重新选择与重新提交；禁止静默覆盖另一客户端修改。

## 3. 导航、布局与共同状态

### 3.1 逻辑路由

以下为目标逻辑路由；由外壳映射到控制平面和设备 Remote，既有 HTTP 路径继续保持契约。

- `/`：聚合会话与欢迎状态；`/sessions/:sessionId?device=:deviceId`：目标设备会话；`/sessions/new`：创建向导；`/sessions/:sessionId/continue`：继续方式与 fork 确认。
- `/projects`、`/artifacts`、`/notifications`：全局入口，当前设备与会话过滤写入 URL；面板详情使用稳定对象标识。
- `/settings/:section`：通用、模型、插件、运行参数、助手、技能、记忆、连接器、自动化、分享、设备、访问、通知、数据与诊断。保留上游区段归属及自建区段顺序。
- `/diagnostics`：本客户端与选定设备的诊断；`/s/:token`：匿名只读快照；`/access` 与 `/access/verify`：访问认证与双因素流程。
- 浏览器前进、后退、刷新与深链接恢复相同对象；对象不存在显示错误和返回列表。访问失效后保存安全的返回目标，认证完成重新读取业务状态，不恢复执行写入。
- iframe 导航消息携带版本、请求标识、目标设备与会话；验证 `origin`、`source`、消息 schema 和允许动作。未知消息拒绝并登记错误，禁止消息携带任意脚本、文件操作或凭据。

### 3.2 尺寸与响应式

宽屏使用[基础设计](<ui-baseline-design.md>)的侧栏、头部、右栏和状态条尺寸。宽度不足时按优先级收起右栏，再收起侧栏；低于 768 CSS 像素使用抽屉导航、全宽主区域与全屏右栏。320、360、390、768、1024、1280、1440 CSS 像素均必须可操作。页面正文不产生横向滚动，代码、宽表格和终端拥有独立横向滚动与可访问名称。

设置表单在窄屏单列排列；保存栏位于可见区域并避开软键盘。底部使用安全区内边距，输入区跟随可视视口调整；旋转、200% 文字缩放与 400% 页面缩放不遮挡发送、审批、返回和关闭动作。图形客户端触控目标至少 44×44 CSS 像素，密集表格使用可聚焦行菜单。拖动分隔条同时支持键盘调整及重置尺寸。

### 3.3 状态矩阵

所有列表、详情、表单、会话都接受共同状态；每个场景同时验证适用的状态，不能用一个全局提示替代字段和业务结果。

- `loading`：保留标题、导航与容器尺寸，声明 `aria-busy`；取消过期读取，旧设备响应不得写入新设备页面。
- `empty`：区分没有记录、没有搜索结果与过滤后为空；提供相应创建、清除过滤或返回动作。
- `error`：显示失败对象、可理解原因与错误码；局部区域重试，保留其他内容及输入。读取失败不得显示零值、未启用或成功。
- `readonly`：保留内容和元数据，去掉可编辑提交入口，显示只读原因；公开快照永远只读。
- `offline`：分别显示控制平面连接与目标设备状态，应用第 2.2 节；只读内容附读取时间。
- `pending`：计数、提出时间与处理入口一致；多项接管按照宿主优先级逐项显示，草稿保留。
- `forbidden`：说明缺少的浏览器、系统或运行时权限，提供对应设置入口；执行权限不能由客户端自行授予。
- `disabled`：标明能力停用或当前平台不可用及启用条件；保留当前业务记录，禁止把停用当成读取失败。
- `danger`：确认影响范围；无权限或离线时不能进入确认成功状态。
- `degraded`：显示依赖、失败时间、最近成功读数时间与影响。Hermes 由 DSH 承载的回合标注“本地执行”，记忆不可达保留当前回合执行。
- `long`：显示服务器提供的阶段、时间、进度及取消语义；未知进度使用不确定进度指示，取消后等待实际终态。
- 所有写操作还具有 `validating`、`submitting`、`succeeded`、`failed`、`conflict`、`unconfirmed` 状态；反馈不能只依赖短暂 Toast。

## 4. 场景规格与验收

### S01 工作会话

入口：[S01 工作会话](<ui-design/complete.html#S01>)。覆盖 UI-01–UI-22、UI-31、UI-35–UI-40、CTX-01–CTX-03。

- 侧栏显示标题、会话类型、来源设备、活动时间、未读与待处理数量；支持标题/内容检索、工作区/设备/时间分组、清除过滤和历史分页。内容检索不可用时保留标题检索并说明范围。删除与恢复入口进入 S24。
- 头部显示标题、设备、目录、模型/provider、权限、助手，支持重命名、分享、导出、第二窗口、血缘与删除。首次进入提供聊天/工作入口、模型配置与目录选择；缺少模型时允许进入设置和阅读界面。
- 消息呈现用户、助手、系统及开发者来源、Markdown、代码复制、链接、引用、附件与产出；解析失败保留可复制原始文本及错误说明。流式输出区分等待首字、正在输出、连接中断、已完成；阅读历史时不自动拉到末尾，显示新消息入口。
- 工具卡片显示名称、状态、耗时、参数摘要及完整结果入口；截断说明包含大小与读取动作。消息反馈支持类型、原因和可选说明，失败保留输入。上下文占用使用宿主读数，0.7 与 0.9 阈值使用文字和符号标注。
- AC-S01：真实创建会话、发送并读取流式事件，消息与权威日志一致；长输出分页/折叠/复制可用。切换设备后没有旧响应污染，模型与 preset 在第一回合后固定。停止按钮只有在宿主确认后呈现终态。

### S02 新建会话与设备目录

入口：[S02 新建与目录](<ui-design/complete.html#S02>)。覆盖 UI-02、UI-03、UI-12、UI-63、PROJ-07。

- 字段：类型 `chat|work`、目标设备、工作目录、可选标题、助手/preset、模型/provider、推理强度、权限档位。工作目录仅工作会话必填；聊天使用宿主规定的聊天环境。标题最多 200 字符，限制由服务端校验并返回。
- 先选择设备，再浏览该设备目录或手动输入绝对路径；更换设备清空旧目录确认及过期结果。桌面原生目录选择仅服务本机设备；远程目录始终通过远程列举/手动输入。目录列表具有父级、当前位置、刷新、权限与越界错误。
- 确认页显示固定的设备、目录、类型与 preset，读取项目默认值和说明；创建幂等，部分成功时显示创建出的会话并提供修复归属入口，禁止重复建立会话。
- AC-S02：在两台真实设备分别创建，检查权威日志与归属中的 `deviceId/cwd`；创建前设备断开返回明确失败。非法目录和取消选择不创建记录，重复点击只创建一条。

### S03 跨设备继续与离线

入口：[S03 跨设备继续](<ui-design/complete.html#S03>)。覆盖 MOB-14、CP-05、CP-06。

- 同时展示“在远程继续”和“在本机继续”的结果说明。fork 表单包含源会话、目标设备、目标目录、历史范围、`full-prefix|compressed`、助手与模型；预估事件数、字符数、附件缺失和压缩损失，隐藏内部副本水位。
- 历史范围在完整回合边界选择。源设备离线时可从可用副本创建本机 fork，确认内容读取时间和范围；副本缺失明确拒绝。活动工具不会重放，源会话继续保持原执行归属。
- 写租约占用显示占用进程与等待/重新读取入口，禁止争抢。提交后跳转新会话并显示来源链；失败保留源会话与填写值。
- AC-S03：远程继续仍使用原编号；本机继续产生新编号、正确本机目录与 `parentSession`。源设备离线发送、审批和终端均失败；恢复联网不增加发送次数，手动发送只产生一个回合。

### S04 审批

入口：[S04 审批](<ui-design/complete.html#S04>)。覆盖 UI-23、UI-29、APR-01–APR-08。

- 卡片字段：工具、脱敏命令/参数摘要、原因、设备、目录、提出时间、失效时刻、能力范围。输入接管只显示当前最高优先级卡片，原草稿保留。
- 会话内允许一次、拒绝、本会话允许、始终允许由实际策略能力决定；扩大范围必须再次确认。全局列表只提供单次允许与拒绝，支持会话过滤、等待列表和统计。
- 决定携带 `callId` 与状态版本，服务端验证未处理及有效期；缺少关联键显示不可处理。处理中锁定本卡片，另一客户端决定、过期、策略变化分别显示具体结果。
- AC-S04：两个真实客户端竞争同一 `callId` 仅一次决定成功；断线不发送决定；宿主收到拒绝后结束对应工具等待。决定事件撤回同关联键通知，审计不丢失。

### S05 提问、计划、目标、子代理与工作流

入口：[S05 执行轨迹](<ui-design/complete.html#S05>)。覆盖 UI-24–UI-28、UI-57、UI-62。

- 提问按 schema 显示标题、说明、单选/多选、自由输入、必填及选择数量；支持多个问题逐项校验。提交、取消、过期和上下文变化分别处理。
- 计划展示完整 Markdown、步骤、当前状态与可编辑反馈；批准执行和提交修改意见通过宿主接管链，当前不支持切换时给出原因。
- 目标展示目标文本、状态、进度、自动继续轮次限制和暂停/恢复/清除；清除说明对执行中的影响。子代理目录显示父子关系、运行/完成/失败、结果与跳转。工作流显示节点依赖、等待、运行、失败与完成；作业展示日志、取消与退出码。

### S18 访问认证、双因素与恢复

## 5. 无障碍、高对比度与键盘验收

- AC-G01 语义：页面有唯一主标题和命名明确的 landmark，跳转链接可直接进入主内容；iframe 标题包含设备与会话，业务表格使用表头与可理解排序说明，文件树/页签/菜单/对话框遵循对应 ARIA 模式。
- AC-G02 焦点：Tab/Shift+Tab 顺序符合阅读顺序；菜单方向键、Enter、Escape、Home/End 完整；模态约束焦点，关闭恢复触发元素。移除对象后聚焦相邻项或列表标题。iframe 内外有明确的跳转按钮，避免键盘被困住。
- AC-G03 字段：每个输入都有可访问名称和帮助关联；错误用 `aria-invalid` 与错误描述关联；必填、选中、展开、禁用及忙碌状态可被读屏读取。图标按钮有名称，提示不依赖悬停。
- AC-G04 实时反馈：读取、成功和进度通过 `role=status`/polite 提示；需要立即处理的失败使用 alert。流式消息按完成的语义片段或回合播报，提供暂停实时播报选项，禁止每个 token 抢占读屏。
- AC-G05 对比度：普通正文、辅助说明、按钮文字至少 4.5:1，重要标题至少 7:1，焦点、边框、图形和状态标识至少 3:1。暗色、亮色、高对比度和 `forced-colors` 均实测；正文大小的状态文字也满足 4.5:1。选中和错误同时使用文字/图形/边框。
- AC-G06 缩放与动作：200% 文字缩放和 400% 页面缩放下内容重排；触控目标至少 44×44；拖放、滑动、缩放、分隔条都有键盘和按钮等价操作；减少动态效果下关闭非必要动画与闪烁。
- AC-G07 长内容：虚拟列表支持读屏获取位置、总数和加载更多，分页后焦点保持稳定；代码、JSON、终端和路径可以选择复制，横向区域具备名称和键盘滚动入口。
- AC-G08 真实辅助技术：Windows 使用键盘与 NVDA，Android 使用 TalkBack，支持的 macOS 使用 VoiceOver 检查关键路径；记录软件版本、动作、朗读结果和具体缺陷。自动可访问性检查与人工辅助技术检查分别保留证据。

## 6. 遥测、安全与验证边界

所有场景的对外可见操作同时交付 span、失败事件及可聚合 `_total` 指标；名称和属性按[遥测规范](<telemetry.md>)登记到统一清单与包声明，业务仅使用统一客户端。导航、读取、提交、拒绝、离线、冲突、超时、权限、限流与取消均有可查询结果。新增信号采用域/操作命名，`error.type` 与 `error.code` 完整；消息内容、工具参数、文件内容、录音、凭据、个人标识与内网地址不进入遥测。

AC-G09：真实控制平面到设备、iframe Remote、Web Push、桌面桥与 CLI 边界传播有效 `traceparent`，关闭时全部停止生成和传播；导出失败只在遥测模块内部计数，不改变业务结果。

AC-G10：私有 HTTP、WebSocket、SSE、文件下载及写入执行认证、同源/CSRF、路径与对象权限检查；外部 HTML、Markdown 链接、SVG、MCP 参数、导入内容使用成熟组件和解析器。浏览器持久化中仅保留经批准的偏好、导航元数据与草稿，令牌按安全存储契约处理。

AC-G11：每个 S01–S32 验收至少记录正常路径和适用的加载、空、失败、只读、离线、待处理、权限、停用、危险、降级及长任务结果；不适用状态写明原因。状态选择器可以审阅版式，真实状态必须由实际断网、服务退出、权限撤销、真实冲突等条件触发。

AC-G12：验证在项目内独立数据根执行，使用真实服务和真实用户动作，不修改用户现有数据、不使用替身通过验收。不得主动使用视觉截图能力；使用 DOM、可访问树、计算样式、事件、数据库记录、文件字节和进程状态形成可复现证据。运行中环境条件不足时明确列出缺失条件，不把设计画板当作功能实现。
