## 2. 设计权威与实现状态

完整设计稿负责产品视觉与页面组成，完整客户端规格负责字段和行为，系统完成设计负责跨组件契约，实施任务负责执行依赖与验收分工。现有[目标形态](<target-shape.md>)继续定义单用户、多设备、单个活动设备 iframe、设备权威日志与 PWA 载体。存在同类细节时，本次完整规格与系统完成设计提供明确的最终目标。

[验收状态](<acceptance.md>)与[功能清单](<ui-feature-inventory.md>)只登记已实现的真实能力。设计稿中名称、路径、消息和读数均为设计示例，未连接业务服务。产品实施完成必须通过真实模型、真实设备、真实存储与对应平台验证。

## 3. 产品规则

- 会话的执行设备与目录创建后保持固定。远程继续使用源设备，本机继续创建带血缘的新会话。
- 所有客户端离线只保留草稿。写操作立即显示失败，恢复后由用户手动发送；在线执行队列断线后暂停并等待用户确认。
- 单用户访问认证管理访问凭据与会话，不建立账号体系。执行节点配对、访问会话与通知订阅各自使用明确的凭据和撤销规则。
- 副本内部序号用于续传与连续性验证，不展示水位与落后条数。只读副本显示内容范围和读取时间。
- 模型、provider、preset 在第一轮开始后固定；Hermes 的运行桥接必须同时满足完整历史、实时审批与真正取消。
- 每个实施工作包同步交付遥测、关闭入口、失败分支与内容隐私约束。

## 4. UI 设计稿打开方式

直接用浏览器打开[完整设计稿](<ui-design/complete.html>)即可，全部资源使用本地相对路径，无需安装依赖、启动业务服务或访问外部网络。离线文件包解压后，从本入口或设计稿页面进入；保持目录结构即可浏览全部场景。入口支持场景锚点，例如 [S04 审批](<ui-design/complete.html#S04>)、[S18 认证](<ui-design/complete.html#S18>)和[S27 移动端](<ui-design/complete.html#S27>)。

需要 HTTP 方式查看时，由实施者在工作区启动静态服务：

```sh
python3 -m http.server 8791 --bind 127.0.0.1 --directory runtime/docs/ui-design
```

此静态服务仅提供设计页面，不替换当前 DeepSeek Harness GUI。

## 5. 委派步骤

1. 领取 WP00，验证版本、设备、存储和真实服务条件；登记独立测试数据根。
2. 按工作包的依赖完成契约、基础组件、系统服务与领域实现。每个 agent 只修改所领取的写入范围。
3. 公共路由、存储入口、profile、构建与遥测登记使用顺序集成子任务，领域任务在集成和真实验证完成后关闭。
4. 每个场景同时检查业务 AC 与通用 AC，记录服务版本、命令、退出代码、存储结果和遥测查询。
5. WP40 汇集实际证据后更新实现状态，缺少平台或服务条件的项目保留明确未完成项。

## 6. 离线文件包

离线交付包保留设计文档、完整 UI 设计稿与基础样式的相对目录。解压后打开其中的 `runtime/docs/ui-design/complete.html`。设计页面不需要网络与构建工具；文档中的实现源码链接需要在完整仓库中使用。文件包不包含凭据、用户会话、依赖目录或运行数据。

## 7. 任务委派文本

```text
任务：<工作包编号与名称>
输入：设计交付入口、系统完成设计、完整客户端规格中的对应场景、实施任务的具体小节。
写入范围：<工作包明确的目录与新文件>；公共入口由集成子任务处理。
依赖：<前置工作包及其验证证据>。
输出：真实实现、对应测试、遥测调用与声明、逐项验收证据。
验收：<AC-Sxx / AC-Gxx / AC-SYSxx> 全部满足；使用真实服务与设备，失败不得静默跳过。
保护：先读取再修改，保留用户已有变更，不修改其他 agent 的范围。
```
