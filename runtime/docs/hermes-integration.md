# 执行体与记忆提供方接入

## 一、能力归属

聊天执行通过标准 `execution` 能力，记忆通过标准 `memory` 能力。用户分别选择提供方，适配器将其接入 DSH 宿主。插件安装、能力绑定、生命周期和范围映射采用[平台契约](plugin-platform.md)，历史、审批与取消采用[系统完成设计](system-completion-design.md)。

DSH 是默认执行体，模型回合、会话日志、工具、审批、目标、工作流和子代理由 DSH 提供。Hermes 是可选的外部执行体，只有完整运行接口通过验收后才能绑定。工作会话在所属设备执行，切换记忆提供方不改变执行设备与目录。

记忆提供方来自用户选择的 DSH 插件。抽取、召回、整理、遗忘和存储由插件维护，平台适配器提供参数映射、权限、结果和生命周期衔接。能力接口不限定所有插件采用相同的 bank、文件格式或记忆层次。

## 二、Hermes 运行接口

现有 Hermes 适配器的入口为 `api_server`，渠道平台插件用于主动投递。以下原生接口必须在所选版本的完整运行组合中验证。

| 用途 | 原生入口 |
|---|---|
| 文本与完整历史输入 | `POST /v1/chat/completions`、`POST /v1/responses` |
| 建立运行 | `POST /v1/runs` |
| 运行事件 | `GET /v1/runs/{run_id}/events` |
| 审批决定 | `POST /v1/runs/{run_id}/approval` |
| 运行干预与停止 | `POST /v1/runs/{run_id}/steer`、`POST /v1/runs/{run_id}/stop` |

标准运行适配器需要 `startHistoryRun`、`getRun`、`answerApproval`、`cancelRun` 和带序号的事件流。完整历史、实时审批、稳定运行标识、状态查询与真实取消必须同时成立。缺少能力时拒绝绑定，单次文本响应无法证明完整运行契约。

协议与 HTTP 翻译集中在根目录 `hermes-adapter/`。设备侧适配器把标准执行请求传给它，DSH 宿主负责会话写入、投影、角色范围和审批展示。无需为每个客户端实现 Hermes 协议。

## 三、记忆插件适配

记忆标准操作、提供方范围、唯一生命周期执行组件、幂等与异步状态的完整定义位于[平台记忆契约](plugin-platform.md#6-记忆标准接口)，社区插件的具体接入决定位于[提供方清单](plugin-platform.md#7-社区记忆插件的接入决定)。

Hindsight 可以通过已公开客户端的 DSH 插件接入，也可以由用户选择的记忆插件内部作为子提供方管理。适配器复用插件的公开服务、SDK 或原生 API。插件已经维护的 Hindsight HTTP 客户端、召回、抽取与队列由插件继续维护。

Hermes 内置记忆属于 Hermes 原生运行生命周期。单独绑定为平台标准记忆提供方，需要独立证明范围访问、管理接口与生命周期关闭语义。在此之前，内置记忆只能作为该执行体声明的原生行为呈现，不能宣称 DSH 工作会话可以读写同一份数据。

平台不会因 Hermes 已启用自动选择其记忆。执行体内置记忆与另一个记忆插件同时影响同一会话时，必须核验写入与召回各自的唯一执行组件及实际读取范围。无法约束原生后台行为的组合不可启用。

## 四、绑定组合

| 执行选择 | 记忆选择 | 行为 |
|---|---|---|
| DSH | 关闭 | 直接使用 DSH 执行，不创建记忆提供方资源 |
| DSH | 已通过验收的记忆插件 | 使用插件适配器，按绑定的范围和生命周期工作 |
| Hermes | 关闭 | 执行体必须能够关闭自身记忆，无法关闭时不能将该组合标记成立 |
| Hermes | 已通过验收的记忆插件 | 完整运行桥接和记忆集成分别验证，核查执行体内部记忆及外部插件的自动行为 |

绑定使用 revision。新回合取得快照，活动回合与已受理任务固定使用原提供方。更换插件不自动迁移已有记忆，也不改变旧记录和异步操作的来源。

## 五、历史、事件与审批

DSH 权威会话日志保存 ChatDSH 的完整有效历史。每个 Hermes 回合使用该历史和稳定的 system、第一条 user 文本，不能假定一次请求会将助手历史写入 Hermes 数据库。工具轨迹作为只读证据保留，跨执行体不重新执行。具体输入、事件和恢复顺序使用[系统运行桥接](system-completion-design.md#6-hermes-完整历史运行桥接)。

外部回复通过合法的回合、步骤和表面事件追加。每条助手消息包含稳定 id、来源 provider/model、内容及 stream。来源登记为实际执行体，用量按来源结算。必须由单一会话写者追加，`flush` 成功后才确认耐久结果。

有活动 Agent 时通过其真实会话追加，无活动 Agent 时取得 `sessionPersistence` 写句柄。两条路径按会话串行化，所有权冲突时明确返回冲突，禁止另一条路径绕过单写者。运行事件先进入持久 inbox，以 `runId/eventId` 去重后追加并推进游标。

外部审批的人工决定关联精确 `run_id/request_id`。用户只能选择执行体当前允许的选项，卡片使用真实审批状态。审批应答立即转发并等待原运行确认，已解决、超时和失效分别展示。未开启 DSH 工具回合的渠道审批使用独立记录与投影，保留精确的外部关联标识。

原生插件记录使用公开 `appendPluginRecord` 和合法 `plugin:` 类型。会话格式迁移可能丢弃可忽略记录，因此关键操作、批准结果和恢复信息进入持久业务记录，显示投影可从它们重建。

## 六、对话转工作

对话转工作创建带血缘的新会话。DSH preset 在首轮后锁定，已有会话不修改 `deviceId/cwd`。用户选择历史范围、目标设备与目录，平台从 DSH 权威历史构造种子，使用 `buildForkSeed`、`ctx.agents.create` 和目标工作区 `attachSession` 完成创建。

种子包含完整的合法事件前缀与原生合成闭合事件，继承数量只计算源事件。新增事件序号取实际日志末端。历史经过有效回合、撤销和压缩规则处理，读取分页至所选范围结束。`parentSession` 指向实际源会话，归属登记由宿主验证。

跨执行体只继承双方支持的文本和已验证的原生块。来源、范围与损失在界面明确展示。首轮使用目标 preset 重建提示词，不承诺继承源执行体的缓存。用户没有授权的其他会话与插件记忆不自动加入种子。

## 七、生命周期与失败

Hermes 可以使用外部服务或由控制平面托管单实例。外部模式不启动和停止该服务，托管模式按配置和在途运行管理生命周期。未选择 Hermes 时不创建相关连接和进程。

记忆插件连接及后台任务由已登记的执行组件创建和释放。Hindsight 等外部服务按提供方配置部署，平台不把某个服务写为所有记忆提供方的必需组件。

执行前配置、版本和范围错误立即拒绝。执行体不可达返回明确错误，不自动更换执行体。请求已经受理或结果未知时继续查询原操作，禁止重放到其他执行体。停止等待真实运行终态，本地中断等待不能表示远端业务已经停止。

记忆未启用、没有适配器、不支持操作、提供方不可达和查询为空分别展示。可选记忆失败后的会话策略必须由用户明确配置，具体行为使用[故障契约](plugin-platform.md#64-可用性与故障)。写入重试仅在提供方支持原生幂等且队列由唯一组件管理时执行。

## 八、开发环境

真实集成验证使用独立数据根和隔离的服务。开发环境编排与变量使用 [dev/README.md](../dev/README.md)，社区插件源码只读核查，不能执行其测试中的替代服务并宣称完整集成通过。

每次验证记录 DSH、提供方、适配器、完整依赖和数据版本。声明兼容、真实装载、标准操作、真实模型与远程服务分别记录证据。

## 九、实施输入

标准接口与提供方实施采用[PA01–PA08](plugin-platform.md#12-实施与验收)。Hermes 完整运行桥接采用[SYS05](implementation-work-packages.md#sys05-hermes-全历史实时事件审批与取消桥接)，产品记忆界面采用 WP15、WP16 和实际支持的操作。每个提供方同步交付遥测、关闭验证、范围验证、数据保留与卸载检查。
